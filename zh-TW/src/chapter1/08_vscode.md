# VS Code 的型別提示

## 本集目標

用 VS Code 看錯誤、查型別、自動完成，不必每次都跑 `npx tsc`。

## 正文

VS Code 內建了 TypeScript，不用另外裝擴充功能。你打字的同時，它就在背後檢查型別。

### 紅色波浪線

建立 `editor.ts`，打下這兩行：

```ts,ignore
let count = 0;
count = "零";
```

還沒存檔，`count` 底下就出現了紅色波浪線。把游標移到波浪線上，會跳出一個小框框，裡面就是跟 `npx tsc` 一樣的錯誤訊息。

寫程式的時候，紅線就是你的第一道防線：**看到紅線，先處理它。**

### 把游標移上去看型別

把錯誤改掉，換成這段：

```ts
const user = { name: "小明", age: 20 };
let city = "台北";

console.log(user, city);
```

把滑鼠游標移到 `user` 上面，會看到：

```text
const user: {
    name: string;
    age: number;
}
```

移到 `city` 上面：

```text
let city: string
```

這就是上一集說的型別推論的結果。**不確定某個東西是什麼型別，就把游標移上去看。** 這招在之後每一章都會一直用到。

> 如果把 `let city` 改成 `const city`，再把游標移上去，會看到 `const city: "台北"`，而不是 `string`。這是故意的，第 5 章會解釋。

### 自動完成

在下一行打 `user.`（`user` 後面加一個點），VS Code 會跳出一個清單，列出 `name` 和 `age`。用上下鍵選、按 Enter 就填進去了。

因為 VS Code 知道 `user` 的型別，所以知道它有哪些屬性。有了自動完成，`nmae` 這種錯字就很難打出來了。

### 問題面板

紅線只會出現在你開著的檔案裡。從上方選單選「檢視」→「問題」，會打開「問題」面板，列出目前所有找到的錯誤，點一下就能跳過去。

### 以 `npx tsc` 為準

VS Code 內建的 TypeScript 版本，不一定和你在 `ts-practice` 裡裝的版本完全一樣，少數情況下，顯示的錯誤訊息會有些微差異。

所以分工是這樣：**寫的時候看紅線，寫完用 `npx tsc` 做最後確認**，結果以 `npx tsc` 為準。

## 重點整理

- VS Code 會在你打字時檢查型別，錯誤顯示成紅色波浪線。
- 把游標移到變數上面，可以看到它的型別。
- 打 `物件.` 會跳出自動完成清單，列出這個物件有的屬性。
- 寫的時候看紅線，寫完用 `npx tsc` 做最後確認。
